# TASK: ROXIE-consistent strand-level self-field peak-field/margin calculation

- **ID**: 0021-roxie-consistent-self-field-margin
- **Status**: draft
- **Model/effort**: Highest effort. This replaces the peak-field-for-margin
  methodology introduced in task 0018 (approved, merged) with a physically
  correct one derived from ROXIE's own documented algorithm. Same rigor bar
  as every geometry/physics task in this project: hand-derive first, then
  live-ROXIE validate **per block/conductor**, not just an aggregated
  worst-case number.

## Background

Tasks 0018/0019/0020 got peak-field/margin parity to a reasonable state
(single-cable-type cases mostly <0.5%/<0.15pp; a CTH_HF-inclusive 30-case
mixed-conductor sweep showed peak field 96.7% within 2% but margin only
73.3% within 2 percentage points, mean 1.28pp, max 4.18pp — see the
coordinator's own sweep log). Critically, several of those margin outliers
show almost **no** peak-field error (e.g. one case: 0.023% peak-field
diff, 4.1pp margin diff) — margin error is not simply inherited from
peak-field error, which means the current peak-field methodology itself is
producing values that are close on average but subtly, systematically
different from what ROXIE actually computes, in a way that gets amplified
by the nonlinear Jc(B,T)-based margin calculation.

The user pointed out two things:

1. **Comparison methodology bug (fix this first, before touching any
   code)**: prior validation scripts compared "DOT's own worst-layer
   margin" against "ROXIE's own worst-layer margin" as two independently
   selected scalars. If DOT and ROXIE pick a *different* layer/block as
   the binding one (plausible when two layers have close margins), the
   reported "margin diff" conflates a real per-block error with a
   worst-block-selection mismatch. **Comparisons must be per-block**: for
   each block/conductor, compare DOT's peak field and margin against
   ROXIE's `PEAK FIELD IN CONDUCTOR N` / per-conductor loadline for the
   *same* conductor, not just the aggregated design-level minimum.

2. **ROXIE has a documented "self field" concept DOT does not implement.**
   From the official CERN ROXIE user documentation
   (`https://roxie.docs.cern.ch/user-documentation/6_analytic_field_calc.html`
   and `5_coil_modelling.html`, fetched directly — read these yourself,
   this summary is not a substitute):

   - Cables are discretized into `N1 * N2` strands for field calculation
     (`N1` = strands in the narrow/thickness direction, `N2` = strands
     across the broad/width direction) — this is the same `n1`/`n2` used
     in the ROXIE `.data` `BLOCK` record columns, and for the CTH cables
     it exactly equals the real strand count (`CTH_HF`/`CXF150HT5`: 40
     strands = 2*20; `CTH_LF`/`CTH_CERN`: 30 strands = 2*15 — verified
     against the real `CABLE` rows in `roxie_CTH_cables.cadata`, matching
     a standard 2-strand-thick Rutherford cable construction).
   - **"Self Field in Strands"**: *"For the calculation of the fields at
     strand-level: take into account also the self field. We define as
     the self-field the maximum value of the field generated by a strand
     on its surface, i.e. `I_strand / (2*pi*r_strand)`."*
   - **"Peak Field in Coil"**: the field is calculated *at strand level*
     — i.e. at each of the `N1*N2` strand positions, not at the turn's
     geometric boundary corners (which is what task 0018's
     `_peak_field_on_own_turns` does today).
   - **Load line position**: *"position of each conductor on the loadline
     is determined and the maximum per block is written to the
     `.output`-file."* — margin is computed per conductor (= physical
     turn instance, matching the `PEAK FIELD IN CONDUCTOR N` numbering
     already observed in `.output` files), and the worst conductor's
     margin is reported per block.

   This means ROXIE's actual peak-field-for-margin algorithm is:
   for each strand (one of a conductor's `N1*N2` filament positions),
   `B_peak_at_strand = B_external(all other strands' currents, in the
   entire design, evaluated at this strand's position) +
   I_strand / (2*pi*r_strand)` (the analytic single-wire self-field,
   which sidesteps the 1/r singularity of evaluating a line current's own
   Biot-Savart field at zero distance from itself). The conductor's peak
   field is the max over its own strands; DOT's current approach (sum
   *all* filaments including the turn's own, evaluate at geometric
   boundary points, no self-field decomposition) is a fundamentally
   different, less physically grounded approximation — this is very
   likely the root cause of the residual gaps found across all margin
   validation so far.

## Goal

1. **Fix the validation/comparison methodology first** (in whatever test
   or sweep code is touched), independent of any implementation change:
   compare DOT vs ROXIE **per block/conductor**, matching them up by
   position (radius/phi/layer index), not by independently selecting each
   side's own worst value. Confirm with the existing (pre-0021) code what
   the *true*, correctly-matched per-block gap looks like before changing
   anything — this tells you how much of the previously-reported margin
   error was a worst-block-selection artifact vs. a real per-block error.
2. Re-architect `_peak_field_on_own_turns` / `load_line_margin_objective`
   in `src/dot/optimize/objectives.py` to follow ROXIE's documented
   algorithm:
   - Discretize each turn into `n1 * n2` filaments using the *real*
     strand layout: `n1=2` (standard 2-strand-thick Rutherford
     construction — confirm this assumption is safe for CTH_HF/CTH_LF,
     both are standard Rutherford cables per their `CABLE` records) and
     `n2 = cable.n_strands / 2` (the cable's real strand count, already
     available via `LayerConductorData.cable.n_strands`, a `CableRecord`
     field) — not an arbitrary large discretization number like task
     0018's `80`.
   - For each filament/strand position, compute the field from every
     *other* filament in the entire design (excluding this filament's own
     source), plus the analytic self-field term
     `I_strand / (2*pi*r_strand)` using the real strand radius
     (`StrandRecord.diameter_mm / 2`, already available via
     `LayerConductorData.strand`) and the actual per-strand current
     (`turn.current_a / cable.n_strands`).
   - A conductor's (turn's) peak field is the max over its own strand
     positions using this formula.
   - Margin stays per-conductor (per-turn), worst-per-layer /
     worst-per-block as appropriate — this part of task 0020's dispatch
     logic likely doesn't need to change, only what "peak field" means.
3. Hand-derive the expected peak field for a simple single-turn case using
   this formula (external-field-plus-self-field decomposition) *before*
   coding, and confirm your implementation reproduces it.
4. **Live ROXIE re-validation, per-block/per-conductor**, not aggregated:
   for at least 3 cases (at least one single-turn, one multi-turn, one
   mixed CTH_HF+CTH_LF multi-layer), compare DOT vs ROXIE's
   `PEAK FIELD IN CONDUCTOR N` values conductor-by-conductor, and
   margin conductor-by-conductor, not just the final worst-of-block
   number. Report the honest per-conductor numbers.
5. Confirm this improves (or at minimum does not regress) the aggregated
   worst-case margin numbers task 0018/0019/0020 already validated live.
